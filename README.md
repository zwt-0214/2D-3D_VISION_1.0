在robomaster26赛季，工程机器人及其经济体系大改，尺寸与重量限制紧张的同时，新的能量单元、科技核心与装甲板不同，仅凭2D的视觉特征其一难以满足其较高精度的位姿需求，其二使用yolopose又会过大地消耗人力标注数据集，且工程机器人没有过高的实时性与动态目标追踪等需求，使得单纯复用自瞄框架并不是合理的选择

    对于工程机器人上位机完成自动取矿和兑矿，笔者做出多版本不同方向的尝试：

    第一版本，笔者采用了foundationpose模型，该模型只需要给出目标的3D建模，仅需利用深度相机提供RGB-D信息，就能估测并追踪目标物体三维世界下的姿态，其零样本泛化的优势能够以较低的人力成本完成26赛季工程机器人获取目标姿态的基本需求

    在使用中，笔者发现：

1.该模型获取目标初始姿态的时间成本较大，故笔者选择配合yolo神经网络的低成本获取目标掩码，输入给foundationpose以目标大致的初始姿态，这样能够结合二者的优点，使得从运行到获取目标姿态的总平均时长压缩至5s以内

2.该模型高度依赖GPU推理，上述效果在robomaster比赛的一般车载电脑上效果一般，盲目提升性能又会给机械设计带来困难，且并不符合工程师思维的设计

3.该模型的追踪能力很强，但对于工程机器人来说，实现自动装配和获取的任务时，目标基本相对于机器人主体静止，即便利用视觉伺服完成闭环，对于任务的提升并不明显

于是，笔者考虑更换或自制其他的6D位姿估计的神经网络，但一般伴随如下痛点：

1.获取3维世界的物体6D位姿真值成本过高

2.精度不足

3.跨域适应性差

4.对于被遮挡物体极容易产生混淆

5.实时性仍不足，且高度依赖硬件性能

    于是，模仿第一版设计思路，笔者设计了第二版本：

    保留了yolo快速获取目标在RGB画面上初始大致位置的优势，对于6D姿态的精度，采用点云配准来保证

相机驱动：

    选择您认为契合工况的深度相机，笔者尝试过英特尔的d435i和奥比中光的GEMINI336L，效果都还不错，请在挑选时注意其工作范围，在距离较近时可能没法获取目标深度值和点云

    驱动只要能获取相机的RGB和点云（可以用深度值转换）即可

yolo_node：

    负责推理目标在二维的RGB里的姿态，可以利用openvino加速CPU推理

    如果您采用了双臂机器人设计，可以在此时利用基本的近大远小检测框大小不同，配合多目标的x值大小的明显差异，可以在这里就筛选出在取矿时适合左臂/右臂抓取的唯一选择，您可以适当调整滤波以防跳变

    如果您的工程需要应付各种参观展示并被要求抓取其他非能量单元物品，您可以尝试用yoloe利用提示词烘焙得到相应模型

pose_estimator：

    主要利用了点云配准来获取目标姿态

    笔者发现，矿石作为一个较小的目标，在不加以筛选就利用点云配准在整个深度相机的点云获取目标姿态时，超90%的点云都是无效的背景

    而利用yolo的bbox直接裁剪所有点云，就能使得效率大幅度提升的同时，还能避免在开局6个能量单元全部在场上，双臂机器人无从下手的局面

    当然，只垂直于相机镜头面切削点云，仍有背景的近40%点云是无意义的背景，即便单纯地测量机械臂最大工作范围作为深度门限，仍距离理论上限有距离，于是笔者设计了深度滤波——原理是求得第一步裁剪bbox后的所有点云深度值的均值，此时，以该深度值为中心，半径为目标（科技核心/能量单元）的外接圆半径 作圆，从而得到了上门限和下门限

    因为深度相机的点云并不是slam后的点云，对于目标物体背后的部分是没有点云的，这使得均值必然比理论上整个背景全被渲染成点云的情况下的深度均值要小，且背景点云相较于目标点云稀疏，所以该方法理论上可行

    经实测，该滤波器能够在不切削目标点云的同时，将需要处理的点云以最大幅度精减点云，使得配准部分能尽可能少处理无关部分

    点云配准方面，依旧采用了粗配准＋精配准的思路

    粗配准使用FPFH(fast point feature histograms)+RANSAC

注意：评估标准可以是fitness，但笔者提出了一种新的方案：

    可以计算配准后每个点与对应点之间的距离的均方根，这样可以比单纯的fitness更能反映平均几何偏差，只不过笔者目前没有时间进行长时间测试

    精配准使用ICP，采用piont-to-plane而非piont-to-point，这样能够避免在能量单元外侧平坦圆形区域滑动

    当目标移动，追踪方面采用ICP，若失败则退回全局配准，如上文所说，在不适用视觉伺服的前提下，定位时基本不发生相对运动

    值得注意的是，能量单元的两端是近似对称的，这使得点云配准的结果可能存在绕y轴180度的两个解，此时，如果是在能量单元存放位置处，你会发现，将能量单元两端处为中心，各做一个半径大于两端圆半径的球体，二者密度较大者一定为有孔的小半径靠中心的一端

    完成配准时，笔者发现，能量单元作为一个基本高度轴对称的物体，对于机械臂抓取而言，其存在一个没有意义的yaw自由度，所以笔者设计了指定rpy的接口，当然，您也可以在机械臂解算方面做出类似设计（比如仅约束xyz，不约束rpy或给出一定容差，相对yaw采样等方案，在此不再赘述）

    获取完成位姿后，lite_motion_planner为自制的机械臂解算部分，笔者希望脱离moveit2的框架，尝试采用更高效的自制运动学解算方案，但这并不意味着moveit不足以完成赛场工况，如果您人力紧张，这也是不错的选择

    但由于在26赛季狗型双臂工程机器人并没有在区域赛上场，且备车并没有为nuc预留位置，故整套流程没有机会经历实战的检验，后续仅在校内做了简单的测试（并没有用上笛卡尔运动学来约束轨迹），机械臂部分仅作为视觉方案的附属，后续如果有时间或者灵感的话笔者会继续开发相关部分，当然欢迎您和笔者交流有关机械臂解算、深度相机、3D视觉、机器学习、自定义客户端、雷达站、飞镖甚至是AI提示词等任意话题

    另外，您可以使用上位机去更快速地制作动作组，只需要录制机械臂的轨迹即可（比如暂存和暂取甚至可以倒放），比下位机打点要方便得多（缺点是小心断串口线）
